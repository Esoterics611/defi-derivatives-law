# 3.4 The "Swap" vs. "Security-Based Swap" vs. "Mixed Swap" Taxonomy

The Dodd-Frank framework splits the OTC derivatives universe into three categories, each governed by a different regulator. Misclassifying an instrument means complying with the wrong regime — or, more commonly in DeFi, complying with neither.

## 3.4.1 The Three Categories

### Swap (CFTC Jurisdiction)

Defined in CEA §1a(47), a "swap" is any agreement, contract, or transaction based on the value of:
- An interest rate or other rate
- A commodity (non-security)
- A currency or exchange rate
- A quantitative measure tied to an economic event (weather, energy prices, economic indices)
- The occurrence or nonoccurrence of an event relating to financial, economic, or commercial consequence

**Key exclusions from the swap definition:** security-based swaps (SEC jurisdiction), forward contracts involving non-financial commodities with intent to deliver, security futures products, any agreement/transaction already subject to the Securities Act or Exchange Act.

### Security-Based Swap (SEC Jurisdiction)

Defined in Exchange Act §3(a)(68), a security-based swap is a swap based on:
- A **narrow-based security index** (9 or fewer component securities, or concentrated weighting)
- A **single security** or loan
- Events relating to a single issuer or issuers of securities in a narrow-based index

The canonical example: a **single-name credit default swap** (CDS on one company's debt) is a security-based swap. A **CDS index** on a broad basket of companies is a swap (CFTC jurisdiction).

### Mixed Swap (Joint CFTC/SEC Jurisdiction)

A mixed swap has characteristics of both a swap and a security-based swap. Example: a derivative that references both an interest rate (CFTC) and a single equity security (SEC). Mixed swaps are subject to **joint** CFTC/SEC rules established through consultation.

## 3.4.2 Classification Decision Matrix

| Underlying Reference | Number of Entities/Assets | Classification | Regulator |
|---------------------|--------------------------|----------------|-----------|
| Interest rate (SOFR, EURIBOR) | N/A | Swap | CFTC |
| Commodity (oil, gold, Bitcoin) | N/A | Swap | CFTC |
| Currency/FX rate | N/A | Swap | CFTC |
| Broad-based security index (S&P 500) | 10+ diversified securities | Swap | CFTC |
| **Single security** (Apple stock) | 1 | **Security-based swap** | **SEC** |
| **Single loan** (one company's debt) | 1 | **Security-based swap** | **SEC** |
| **Narrow-based security index** | ≤9 securities or concentrated | **Security-based swap** | **SEC** |
| Interest rate + single equity | Mixed reference | **Mixed swap** | **Both** |

## 3.4.3 DeFi Application: When Does This Taxonomy Matter?

The swap taxonomy becomes critical when a DeFi protocol offers derivatives on tokens with uncertain regulatory classification:

| DeFi Product | Underlying | If Underlying = Commodity | If Underlying = Security |
|-------------|-----------|--------------------------|------------------------|
| Perpetual future on Token X | Token X | Swap → CFTC | Security-based swap → SEC |
| Options on Token X | Token X | Commodity option → CFTC | Security option → SEC |
| CDS-like protection on Token X's protocol | Token X issuer's credit | If Token X = commodity → Swap → CFTC | If Token X = security → SBS → SEC |
| Synthetic asset tracking Token X | Token X price | Total return swap → CFTC | TRS on security → SEC |
| Index of 5 DeFi tokens | Multiple tokens | If all = commodities → Swap → CFTC; if narrow-based security index → SEC | Security-based swap → SEC |

!!! danger ""
    **The Multi-Token Index Problem**: A DeFi protocol that creates a derivatives product referencing a basket of tokens faces a compound classification problem. Each token in the basket must be individually classified as a commodity or security. If the basket contains any securities and qualifies as a "narrow-based security index," the entire derivative shifts from CFTC jurisdiction to SEC jurisdiction (or becomes a mixed swap). A protocol that adds one new token to an index could inadvertently change the regulatory classification of its entire product.


## 3.4.4 The Joint CFTC/SEC Product Definitions Rule

In 2012, the CFTC and SEC jointly adopted the **Further Definition of "Swap," "Security-Based Swap," and "Security-Based Swap Agreement"; Mixed Swaps** rule (77 FR 48208). This 700+ page final rule established detailed guidance on classifying borderline instruments.

Key clarifications from the joint rule:

| Question | Answer |
|----------|--------|
| Are insurance products swaps? | No — if state-regulated, they are excluded from the swap definition |
| Are consumer/commercial transactions swaps? | No — ordinary commercial agreements (employment contracts, mortgages) are excluded |
| Are FX swaps and forwards "swaps"? | They are in the statutory definition, but the Treasury Secretary exercised authority to exempt them from most Title VII requirements |
| Are total return swaps on a broad-based index classified how? | As swaps (CFTC) — the broad-based index keeps them out of security-based swap territory |
| What about instruments with both commodity and security features? | Case-by-case analysis; the agencies can designate mixed swaps jointly |

!!! success "AI Practitioner Note"
    The swap taxonomy is a classification problem — the kind of structured analysis AI handles well.

    **Prompt Template:**
    ```
    Classify the following derivative instrument under the Dodd-Frank taxonomy:

    Product description: [describe the DeFi derivative]
    Underlying reference: [what does the payoff depend on?]
    Counterparties: [who trades this — retail or institutional?]

    Determine:
    1. Is this a "swap" (CEA §1a(47))?
    2. Is this a "security-based swap" (Exchange Act §3(a)(68))?
    3. Is this a "mixed swap"?
    4. Does any exclusion from the swap/SBS definitions apply?

    For each determination, cite the specific statutory definition 
    and identify which elements are met or not met.
    If the underlying's classification as commodity vs. security is 
    uncertain, analyze BOTH scenarios.
    ```

    **What to Verify:** AI models often default to "swap" classification without adequately analyzing whether the underlying is a security. Always force the AI to explicitly analyze the underlying's classification before classifying the derivative.
