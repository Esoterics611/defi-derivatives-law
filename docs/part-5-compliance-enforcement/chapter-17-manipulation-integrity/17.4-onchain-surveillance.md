## The On-Chain Data Advantage

Every blockchain transaction is permanently recorded, timestamped, and publicly accessible. For surveillance purposes, this is transformative. TradFi compliance officers work with fragmented data across proprietary systems, dark pools, and OTC venues. DeFi surveillance works with a single, immutable, comprehensive dataset.

The raw data is all there: every swap, every deposit, every liquidation, every governance vote, every token transfer. The challenge is not access — it's analysis. Converting billions of transactions into actionable surveillance intelligence requires sophisticated tooling.

## The Surveillance Tool Landscape

| Tool | Primary Function | Strengths | Limitations |
|------|-----------------|-----------|-------------|
| **Chainalysis** | Compliance and investigation; wallet attribution, risk scoring | Largest attribution database; regulatory acceptance; AML focus | Enterprise pricing; less DeFi protocol-level depth |
| **Elliptic** | Compliance screening, transaction monitoring | Strong regulatory relationships; cross-chain coverage | Similar to Chainalysis — AML focus, less manipulation detection |
| **Nansen** | Wallet labeling, smart money tracking, portfolio analytics | DeFi-native; real-time dashboards; token flow analysis | Attribution accuracy varies; labels can be stale |
| **Arkham Intelligence** | Entity attribution, on-chain intelligence, alert system | Aggressive de-anonymization; bounty system for attribution | Privacy concerns; attribution quality varies |
| **Dune Analytics** | Custom SQL queries on blockchain data | Fully customizable; community-built dashboards; free tier | Requires SQL knowledge; query performance varies; not real-time |
| **EigenPhi** | MEV analysis, DeFi transaction decoding | Best-in-class MEV detection; transaction-level decomposition | Narrow focus on MEV; limited historical data |
| **Flashbots Protect** | MEV protection and transparency | Transaction-level MEV attribution; searcher profiling | Ethereum-focused; not a surveillance tool per se |

## Analytical Approaches

### Wash Trading Detection

The core challenge: identifying when two or more addresses are controlled by the same entity. Blockchain addresses are pseudonymous — there's no name attached — but behavioral patterns reveal connections.

**Wallet clustering signals:**
- Funding source: multiple addresses funded from the same origin wallet
- Timing correlation: addresses that transact in synchronized patterns
- Gas behavior: consistent gas price selection, suggesting the same software or operator
- Token flow: assets flowing in circular patterns between addresses
- Interaction overlap: addresses that interact with the same obscure contracts or protocols

Once wallets are clustered, detecting wash trading is straightforward: if clustered wallets trade with each other, those trades are potentially wash trades.

### Sandwich Attack Identification

Sandwich attacks have a distinctive on-chain fingerprint:

1. A buy transaction by address A in block N, targeting the same token pair as a pending user swap
2. The user's swap executing in block N, at a worse price than the pre-attack market
3. A sell transaction by address A in block N, immediately after the user's swap

The temporal and positional relationship (same block, sequential transaction ordering) is the detection key. Tools like EigenPhi automate this analysis and can attribute profits to specific searcher addresses.

### Position Concentration Monitoring

Monitoring for unusual position building — especially before governance votes, oracle updates, or token unlocks — requires tracking aggregate positions per entity (using wallet clustering) across protocols. A single entity accumulating 15% of a protocol's TVL across 50 wallets is invisible at the address level but apparent after clustering.

## The Pseudonymity Problem

On-chain surveillance can detect behavior but often cannot identify the person. This creates an enforcement gap:

**What you CAN see:** Transaction patterns, wallet relationships, MEV extraction, position sizes, timing, and economic outcomes. The behavior is fully transparent.

**What you CANNOT see:** The person behind the wallet. Pseudonymous addresses don't reveal names, locations, or organizational affiliations. Even with wallet clustering, the cluster resolves to a set of addresses, not a legal name.

**Bridging the gap:** Enforcement agencies bridge the pseudonymity gap through:
- **Exchange records**: When on-chain funds flow to/from centralized exchanges (which have KYC records), the exchange can identify the account holder
- **IP analysis**: When wallets interact with web services (RPC endpoints, dApps), IP addresses may be logged
- **Blockchain forensics**: Specialized firms (Chainalysis, Elliptic) maintain proprietary attribution databases linking addresses to known entities
- **Informants and cooperation**: Traditional investigative techniques remain effective — the Mango Markets case relied heavily on Eisenberg's own public statements

!!! info "AI Practitioner Note: Building an AI Surveillance Pipeline"
    For DeFi protocol monitoring, design a multi-stage pipeline:

    *"Design an AI-powered surveillance pipeline for [protocol name] that: Stage 1 — Data ingestion: index all protocol events (swaps, deposits, liquidations, governance votes) using [The Graph / custom indexer]. Stage 2 — Wallet clustering: apply behavioral clustering algorithms to group addresses by funding source, timing patterns, and interaction overlap. Stage 3 — Pattern detection: for each surveillance rule (wash trading, sandwich attacks, position concentration, pre-governance accumulation), define detection logic with specific thresholds and alert criteria. Stage 4 — Alert triage: rank alerts by severity (estimated economic impact, confidence level, regulatory significance). Stage 5 — Investigation support: for high-severity alerts, generate a forensic report including transaction timeline, profit/loss calculation, and relevant CEA provisions."*

    **What to Verify:** AI-generated pipeline designs will be architecturally sound but may underestimate the engineering complexity of real-time blockchain data processing. Wallet clustering accuracy is the critical bottleneck — poor clustering generates false positives (legitimate traders flagged) and false negatives (manipulators missed).

## Section Summary

- On-chain data provides comprehensive surveillance coverage — every transaction is visible, timestamped, and permanent
- Key tools: Chainalysis (compliance), Nansen (DeFi analytics), Arkham (attribution), Dune (custom queries), EigenPhi (MEV)
- Wallet clustering is the foundational analytical technique — linking pseudonymous addresses to entities enables wash trading detection and position monitoring
- The pseudonymity gap remains a significant enforcement challenge, bridged through exchange records, IP analysis, and traditional investigative techniques
- AI-powered pipelines can automate detection but require careful calibration of clustering accuracy and alert thresholds
