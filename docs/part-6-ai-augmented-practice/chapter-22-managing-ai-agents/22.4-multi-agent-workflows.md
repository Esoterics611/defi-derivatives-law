# 22.4 Multi-Agent Workflows for Derivatives Practice

!!! info "Section Objectives"
    After completing this section, you will be able to:

    - Implement four production-ready multi-agent workflows for derivatives compliance
    - Map agent handoff points and human decision points in each workflow
    - Design circuit breakers that prevent error propagation across agents
    - Apply the human-in-the-loop principle to determine which decisions must remain human

---

## Production Multi-Agent Workflows

The following four workflows represent the highest-value applications of multi-agent AI systems in derivatives practice. Each can be implemented with current AI technology and provides measurable efficiency gains.

### Workflow 1: New Counterparty Onboarding

**Scenario**: Your DeFi protocol is onboarding an institutional counterparty for OTC derivatives trading. You need background research, risk assessment, ISDA documentation, and compliance sign-off.

```
Step 1: Research Agent
  Input: Counterparty name, jurisdiction, LEI
  Tasks: Pull corporate registry data, check sanctions lists (OFAC SDN),
         search CFTC enforcement database, identify regulatory status
         (is counterparty a registered SD/MSP/ECP?)
  Output: Counterparty profile with risk flags

Step 2: Analysis Agent
  Input: Counterparty profile from Step 1
  Tasks: Classify counterparty under CEA (ECP, SD, MSP, retail),
         assess eligible contract participant status per CEA §1a(18),
         identify applicable regulatory requirements, assess credit risk
  Output: Regulatory classification memo + risk assessment

  >>> HUMAN CHECKPOINT: Review classification and approve/reject <<<

Step 3: Drafting Agent
  Input: Classification memo + standard ISDA template library
  Tasks: Generate ISDA Schedule with appropriate elections for
         counterparty type, draft CSA terms, prepare required
         compliance documentation
  Output: Draft ISDA Schedule + CSA + compliance docs

Step 4: Analysis Agent (second pass)
  Input: Draft documents from Step 3
  Tasks: Review draft for internal consistency, check elections
         against regulatory requirements, verify defined terms
  Output: Review memo with suggested revisions

  >>> HUMAN CHECKPOINT: Final review and approval <<<
```

### Workflow 2: Enforcement Action Response

**Scenario**: The CFTC files an enforcement action against a protocol with similar architecture to yours. You need to assess exposure and prepare a response strategy.

```
Step 1: Intake Agent
  Input: Enforcement order PDF
  Tasks: Parse order into structured data — respondent, violations
         alleged, statutory basis, factual findings, penalties,
         remedial requirements
  Output: Structured enforcement order summary

Step 2: Research Agent
  Input: Enforcement summary + your protocol specifications
  Tasks: Find all prior enforcement actions with similar fact patterns,
         identify distinguishing factors, locate relevant CFTC guidance
         or no-action letters
  Output: Precedent analysis with comparison table

Step 3: Analysis Agent
  Input: Enforcement summary + precedent analysis + protocol specs
  Tasks: Assess overlap between enforcement facts and your protocol's
         architecture, identify potential violations, evaluate strength
         of any defenses (decentralization, jurisdiction, exemptions)
  Output: Exposure assessment memo with risk ratings per violation

  >>> HUMAN CHECKPOINT: Review exposure assessment <<<

Step 4: Drafting Agent
  Input: Exposure assessment + response strategy (from human input)
  Tasks: Draft internal risk memo for governance, prepare board/DAO
         communication, draft remediation plan if warranted
  Output: Response package — risk memo, communication draft, action plan

  >>> HUMAN CHECKPOINT: Approve all communications and actions <<<
```

### Workflow 3: Regulatory Change Management

**Scenario**: The CFTC publishes a proposed rule that may affect your protocol's operations. You need impact analysis, a comment letter strategy, and implementation planning.

```
Step 1: Surveillance Agent
  Input: Federal Register RSS feed / CFTC.gov alert
  Tasks: Detect new proposed rule, determine relevance to DeFi
         derivatives protocols
  Output: Regulatory alert with relevance score

Step 2: Intake Agent
  Input: Full proposed rule text
  Tasks: Parse rule into sections, extract key requirements, identify
         affected entities, note comment deadline
  Output: Structured rule summary

Step 3: Analysis Agent
  Input: Structured rule summary + protocol specifications
  Tasks: Assess impact of each provision on protocol operations,
         classify as compliant/non-compliant/uncertain for each
         requirement, estimate implementation effort
  Output: Impact assessment matrix

Step 4: Research Agent
  Input: Impact assessment + affected transactions
  Tasks: Identify all current transactions or protocol features
         affected by the proposed rule, quantify the scope of impact
  Output: Affected items inventory with remediation requirements

  >>> HUMAN CHECKPOINT: Strategic decision — comment, comply, or both <<<

Step 5: Drafting Agent
  Input: Impact assessment + strategic direction from human
  Tasks: Draft comment letter (if commenting), draft implementation
         plan (if complying), prepare timeline and resource estimate
  Output: Comment letter draft + implementation plan
```

### Workflow 4: DeFi Protocol Compliance Review

**Scenario**: Your team is evaluating whether to deploy a new DeFi derivatives protocol feature. You need a comprehensive regulatory compliance review before launch.

```
Step 1: Intake Agent
  Input: Smart contract code + protocol documentation + feature specs
  Tasks: Parse smart contract functions, identify economic mechanics,
         map user flows, extract fee structures and governance parameters
  Output: Structured protocol analysis — functions, economics, governance

Step 2: Analysis Agent
  Input: Structured protocol analysis
  Tasks: Classify each protocol function under CEA definitions —
         is this a swap? A future? An option? Is the protocol a DCM,
         SEF, or trading facility? Are users ECPs?
  Output: Regulatory classification report with element-by-element analysis

Step 3: Research Agent
  Input: Regulatory classifications
  Tasks: Check each classification against enforcement precedent —
         has the CFTC addressed this type of protocol? What was the
         outcome? Are there relevant no-action letters?
  Output: Precedent report with risk-weighted citations

Step 4: Analysis Agent (second pass)
  Input: Classification + precedents + protocol specs
  Tasks: Produce comprehensive compliance memo — violations identified,
         defenses available, risk ratings, recommended modifications
  Output: Compliance assessment memo

  >>> HUMAN CHECKPOINT: Go/no-go recommendation <<<

Step 5: Drafting Agent
  Input: Compliance assessment + human direction
  Tasks: Draft required disclosures, terms of service modifications,
         geofencing requirements, or registration strategy
  Output: Compliance implementation documents
```

## Error Propagation and Circuit Breakers

In multi-agent workflows, errors compound. If the Intake Agent misparses a critical provision, the Analysis Agent analyzes the wrong facts, the Drafting Agent produces documents based on flawed analysis, and the entire output is unreliable.

**Circuit breaker design:**

1. **Confidence thresholds**: Each agent outputs a confidence score. If below threshold (e.g., 70%), the pipeline pauses for human review
2. **Consistency checks**: When multiple agents analyze the same document, compare outputs for consistency. Divergence triggers review
3. **Critical field validation**: For key data points (dollar thresholds, entity classifications, registration status), require the value to be extractable from the source text — if the agent cannot point to the specific text, flag for human verification
4. **Escalation triggers**: Certain fact patterns automatically escalate to human review — novel legal questions, potential criminal liability, cross-border complications

## The Human-in-the-Loop Principle

Not every decision can be delegated to AI. The following must remain human decisions:

| Decision | Why It Must Be Human |
|----------|---------------------|
| **Regulatory classification of a novel instrument** | No enforcement precedent to rely on; requires judgment about how regulators will interpret the law |
| **Risk tolerance determinations** | Business judgment that reflects organizational values, not legal analysis |
| **External communications** | Regulatory filings, comment letters, and counterparty communications carry professional and legal consequences |
| **Go/no-go for product launches** | Combines legal, business, reputational, and strategic considerations that AI cannot weigh |
| **Settlement or litigation decisions** | Requires assessment of non-legal factors: publicity risk, precedent-setting concerns, resource allocation |
| **Reporting potential violations** | Ethical and legal obligations that require human judgment about materiality and intent |

The principle: **AI produces analysis; humans make decisions.** Every workflow must include explicit points where a human reviews, approves, modifies, or rejects the AI's output before it progresses or exits the system.
