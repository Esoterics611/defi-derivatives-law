# 20.3 AI-Assisted Smart Contract Auditing

!!! info "Section Objectives"
    After completing this section, you will be able to:

    - Identify derivatives-specific audit categories for DeFi smart contracts
    - Use AI to review smart contract code for regulatory compliance issues
    - Combine AI analysis with formal verification tools (Certora, Slither, Mythril)
    - Verify AI audit findings against known vulnerability patterns

---

## The Convergence: Legal Review + Code Audit

The DeFi derivatives lawyer's unique skill is the ability to review both the legal documentation AND the smart contract code that implements it. This convergence — ISDA-style legal analysis plus Solidity audit — is where the highest-value work lives.

Traditional smart contract audits focus on security: re-entrancy, integer overflow, access control, flash loan vulnerabilities. A derivatives-specific audit adds a layer: does the contract implement the economic terms correctly? Does the liquidation mechanism comply with regulatory requirements? Are oracle dependencies creating legal exposure?

AI models can review smart contract code with surprising effectiveness — they understand Solidity syntax, can trace execution paths, and can identify common vulnerability patterns. The derivatives-specific prompting is what transforms a generic code review into a regulatory compliance audit.

## Derivatives-Specific Audit Categories

| Audit Category | What to Check | AI Prompt Focus | Common AI Errors | Human Verification |
|---------------|--------------|----------------|-----------------|-------------------|
| **Economic logic** | Does the contract calculate payoffs correctly? (option pricing, perpetual funding, swap cashflows) | "Verify that this contract's settlement calculation matches [economic formula]" | AI may miss edge cases: negative funding rates, extreme price scenarios, rounding | Test with boundary values and adversarial inputs |
| **Liquidation mechanics** | Are liquidation triggers, penalties, and collateral seizure implemented correctly? | "Analyze the liquidation function for fairness, timing, and price dependency" | AI may miss race conditions between oracle updates and liquidation execution | Simulate liquidation scenarios with block-level timing |
| **Oracle dependency** | What oracles does the contract use? Are they manipulable? What happens during oracle failure? | "Identify all external price feeds and assess manipulation resistance" | AI may identify the oracle source but miss TWAP vs. spot distinction or staleness checks | Review oracle contracts separately; test with stale/manipulated prices |
| **Access control** | Who can modify parameters? Pause the contract? Upgrade logic? | "Map all privileged functions, their access requirements, and what they control" | AI is generally good here but may miss proxy upgrade patterns | Verify against deployed contract state, not just source code |
| **Regulatory compliance** | Does the contract implement position limits? KYC gates? Reporting hooks? | "Assess this contract against CFTC requirements for [swap/option/futures] platforms" | AI applies generic compliance concepts; may miss derivatives-specific requirements | Cross-reference against specific CFTC rules from Parts I-V |
| **Composability risk** | How does this contract interact with other protocols? What happens if a dependency fails? | "Trace all external contract calls and assess failure modes for each dependency" | AI may not have current knowledge of dependency contracts | Review each external dependency's documentation and audit status |

## The AI + Tools Workflow

AI review is most effective when combined with specialized security analysis tools:

**Step 1: Static analysis with Slither.** Run Slither (or similar) to catch low-level vulnerabilities: re-entrancy, unchecked return values, dangerous delegatecalls. These are mechanical checks that tools handle better than AI.

**Step 2: AI code review for logic and compliance.** Feed the contract to an AI model with derivatives-specific prompting:

```
Review this Solidity smart contract for a [perpetual futures / options / lending] protocol. Analyze:

1. ECONOMIC LOGIC: Does the settlement/payoff calculation correctly implement [formula]? Trace the math step by step. Identify edge cases where the calculation could produce incorrect results.

2. LIQUIDATION: Review the liquidation mechanism. Is the liquidation threshold appropriate? Can liquidation be front-run? What happens if the oracle price is stale during liquidation?

3. ORACLE RISK: Identify all price feeds. Can any be manipulated within a single block? Within a TWAP window? What's the fallback if the oracle fails?

4. REGULATORY: Does this contract provide infrastructure for: position limits, reporting, access control/KYC gates, or circuit breakers? If not, what modifications would be needed for CFTC compliance?

For each finding, rate severity (Critical/High/Medium/Low) and provide the specific line numbers.
```

**Step 3: Formal verification with Certora/Mythril.** For critical invariants (e.g., "total collateral must always exceed total debt"), use formal verification tools that mathematically prove properties hold across all possible execution paths. AI cannot replace formal verification for safety-critical invariants.

**Step 4: Human expert review.** The derivatives lawyer reviews AI and tool findings, traces cross-contract interactions, and assesses the regulatory compliance implications that require legal judgment.

!!! info "AI Practitioner Note: Derivatives-Specific Smart Contract Audit"
    For the most comprehensive audit, use a layered prompting approach:

    *Pass 1 (Economic):* "Verify this contract's core economics. For each function that calculates a payment, settlement, or liquidation amount, trace the mathematical formula and confirm it matches [specification]. Test with extreme inputs: price = 0, price = MAX_UINT, negative funding rate, 100% collateral drop."

    *Pass 2 (Security):* "Identify all re-entrancy risks, flash loan vulnerabilities, and front-running opportunities. For each external call, assess whether the contract state is consistent if the call reverts or is manipulated."

    *Pass 3 (Regulatory):* "Assess this contract against CEA requirements for a [registered DCM / swap execution facility / commodity pool]. Identify every regulatory requirement from Chapters 16-19 that this contract does not satisfy, and propose smart contract modifications for each gap."


!!! warning ""
    **What to Verify:** AI cannot reliably identify all re-entrancy vulnerabilities or complex state-dependent bugs. AI's pattern matching is good for known vulnerability types but weak for novel attack vectors that combine multiple contract interactions. Always pair AI review with specialized security tools AND manual expert review for anything deployed with real funds.

## Section Summary

- The DeFi derivatives lawyer audits both legal terms and smart contract code — this convergence is the unique skill
- Derivatives-specific audits add economic logic, liquidation mechanics, oracle dependency, and regulatory compliance to standard security review
- The optimal workflow layers: Slither (static analysis) → AI (logic + compliance) → Certora (formal verification) → human expert (judgment)
- AI catches 70-80% of issues in a first pass but misses novel attack vectors and complex cross-contract interactions
